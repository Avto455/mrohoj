# Техническое задание: UI-игра «ПРОСВЕТ» (Unity / C#)

## 1. Общая концепция

Разрабатывается двухмерная UI-игра в Unity.

Игрок выступает в роли врача, который обследует пациентов на наличие паразитов и при необходимости проводит их хирургическое извлечение.

Вся игра происходит через один основной интерфейс. Перемещение персонажа по игровому миру, полноценная 3D-сцена и физическая симуляция не нужны.

Основная игровая сессия:

1. Показать карточку пациента.
2. Перейти к рабочему интерфейсу.
3. Использовать рентген для обследования.
4. Переключиться в режим скальпеля.
5. Обвести паразита на теле пациента.
6. Нажать кнопку завершения приёма.
7. Проверить результат операции.
8. Показать статус пациента и перейти к следующему.

## 2. Основной UI

Главный экран содержит:

- Изображение пациента.
- Центральную рабочую область.
- Три кнопки справа:
  - X-RAY.
  - SCALPEL.
  - EXIT.

Расположение элементов должно соответствовать существующему пользовательскому концепту.

Не придумывать новую композицию интерфейса и не заменять пользовательские изображения.

## 3. Система режимов

Создать enum ToolMode:

- None.
- XRay.
- Surgery.

Одновременно может быть активен только один режим.

### None

- Пациент отображается по центру.
- Рентгеновский экран скрыт.
- Рисование недоступно.

### XRay

При выборе кнопки X-RAY:

- Переместить пациента в левую часть экрана.
- Показать рентгеновское изображение по центру.
- Подсветить кнопку X-RAY.
- Отключить возможность хирургического рисования.
- Сохранить информацию о том, что пациент был обследован.

### Surgery

При выборе кнопки SCALPEL:

- Вернуть пациента в центральную часть экрана.
- Скрыть центральный рентгеновский экран.
- Активировать прозрачную область рисования поверх пациента.
- Визуально выделить кнопку SCALPEL.
- Разрешить рисование мышью.

Режим Surgery недоступен до первого использования XRay.

### Переключение режимов

Кнопки X-RAY и SCALPEL должны переключать режим напрямую.

Выбор одного режима автоматически выключает другой.

Важно: кнопка другого инструмента остаётся доступной для переключения. Блокируется только взаимодействие с неактивным инструментом.

Кнопка EXIT доступна постоянно.

## 4. Карточка пациента

Перед началом приёма показывать отдельную UI-панель с данными:

- Имя пациента.
- Возраст.
- Жалобы.
- История болезни.

После нажатия кнопки начала обследования карточка скрывается и открывается основной интерфейс.

Данные пациентов должны задаваться через ScriptableObject, а не быть жёстко прописаны внутри UI-скриптов.

## 5. Данные пациента

Создать ScriptableObject PatientCase.

Поля:

- patientName: string.
- age: int.
- complaint: string.
- medicalHistory: string.
- patientSprite: Sprite.
- xraySprite: Sprite.
- parasites: List<ParasiteTarget>.

ParasiteTarget:

- center: Vector2.
- radius: Vector2.

Координаты center и radius нормализованы относительно изображения пациента и находятся в диапазоне 0–1.

Если список parasites пустой, пациент не заражён.

Все данные должны редактироваться через Inspector Unity.

## 6. Рентген

При активации XRay:

- Отобразить xraySprite текущего пациента.
- Скрыть изображение рентгена при выходе из режима.
- Не генерировать изображения автоматически.
- Использовать изображения, назначенные через Inspector.

На данном этапе достаточно статичного рентгеновского изображения.

Масштабирование и перемещение снимка можно добавить отдельным этапом, если основная механика уже работает.

## 7. Хирургическое рисование

В режиме Surgery игрок рисует замкнутый контур мышью поверх изображения пациента.

Требования:

1. Обрабатывать ввод только при активном режиме Surgery.
2. Начинать рисование при нажатии ЛКМ внутри области пациента.
3. Добавлять точки при движении мыши.
4. Отображать линию на экране.
5. При отпускании ЛКМ проверять замыкание контура.
6. Незамкнутый контур не считать законченной операцией.
7. Сохранять завершённые контуры до окончания приёма.
8. Поддерживать несколько отдельных контуров для нескольких паразитов.

Рисование не должно работать по всей области Canvas, только поверх изображения пациента.

Для визуализации линии допустимо использовать UI Image-сегменты или другой подходящий UI-способ.

Не использовать дополнительные внешние пакеты без необходимости.

## 8. Проверка операции

Создать отдельный SurgeryEvaluator.

Он получает:

- Данные ParasiteTarget текущего пациента.
- Список нарисованных контуров.

Проверка:

1. Каждый паразит должен полностью оказаться внутри отдельного контура.
2. Контур не должен быть чрезмерно большим.
3. Для приблизительной проверки площади использовать площадь полигона и площадь целевой эллиптической области.
4. Допустимый коэффициент превышения площади сделать настраиваемым через Inspector.

Для проверки попадания границы паразита в контур можно использовать несколько контрольных точек на эллипсе и алгоритм Point in Polygon.

Не требуется сложная физика, моделирование тканей или движение паразитов.

## 9. Возможные результаты

Создать enum PatientOutcome:

- HealthyDischarged.
- SuccessfulExtraction.
- MissedParasite.
- PartialExtraction.
- UnnecessarySurgery.
- ExcessiveDamage.

Логика:

| Условие | Результат |
|---|---|
| Паразитов нет, операции нет | HealthyDischarged |
| Паразитов нет, игрок провёл операцию | UnnecessarySurgery |
| Все паразиты извлечены корректно | SuccessfulExtraction |
| Не все паразиты попали в контуры | PartialExtraction |
| Игрок не провёл операцию при наличии паразита | MissedParasite |
| Область операции слишком большая | ExcessiveDamage |

Приоритет проверки: сначала определить чрезмерное повреждение, затем полноту извлечения.

После проверки показать ResultPanel с названием исхода и коротким описанием.

Не использовать графические сцены повреждений. Результаты должны передаваться через текст, звук и интерфейс.

## 10. Завершение приёма

Кнопка EXIT:

- Выключает активный инструмент.
- Останавливает ввод мыши.
- Передаёт текущие контуры в SurgeryEvaluator.
- Получает PatientOutcome.
- Скрывает рабочий интерфейс.
- Показывает ResultPanel.

После результата кнопка NEXT PATIENT загружает следующего пациента.

После последнего пациента показывается итоговый отчёт смены.

## 11. Архитектура скриптов

Предлагаемые компоненты:

- GameFlowController — управление последовательностью игровых экранов и пациентами.
- PatientCase — ScriptableObject с данными пациента.
- ToolModeController — выбор и переключение режимов.
- SurgeryDrawingController — обработка мыши и отрисовка контуров.
- SurgeryEvaluator — проверка точности операции.
- PatientResultView — отображение исхода.

Не создавать избыточную архитектуру, систему событий общего назначения или сложные менеджеры.

## 12. Важные ограничения

- Не создавать 3D-геймплей.
- Не добавлять перемещение персонажа.
- Не добавлять инвентарь.
- Не добавлять систему времени и смены суток.
- Не добавлять лабораторные анализы.
- Не добавлять динамический рост паразитов.
- Не добавлять ИИ паразитов.
- Не добавлять мультиплеер.
- Не генерировать новые художественные ассеты вместо существующих.
- Не изменять существующий пользовательский арт без разрешения.
- Не добавлять сторонние Unity-пакеты без необходимости.

## 13. Порядок реализации

Работать поэтапно.

Этап 1:
Реализовать переключение UI между None, XRay и Surgery. Проверить перемещение пациента и показ рентгеновского изображения.

Этап 2:
Реализовать рисование замкнутых контуров поверх пациента и сохранение нескольких контуров.

Этап 3:
Реализовать SurgeryEvaluator и проверку одного пациента с одной личинкой.

Этап 4:
Реализовать PatientCase, карточку пациента, ResultPanel и переход к следующему пациенту.

Этап 5:
Проверить все результаты: здоровый пациент, успешная операция, пропущенный паразит, несколько паразитов и чрезмерно большая область операции.

После каждого этапа проверить отсутствие ошибок компиляции и работоспособность в Play Mode.

Сначала изучить существующую структуру Unity-проекта и сцену. Не удалять и не перестраивать существующие объекты без необходимости. Использовать уже имеющиеся Canvas, изображения и интерфейсные элементы, если они присутствуют.

Начать с минимальной рабочей версии одного пациента, не пытаться реализовать весь проект одним большим изменением.
